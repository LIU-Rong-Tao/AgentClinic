# AgentClinic 功能规格

仅用于本项目。将课程的重复功能规格提示词保存为工作流程，保持中文讲解和小步推进。

## 读取与确定范围

- 在仓库根目录读取 specs/mission.md、specs/tech-stack.md、specs/roadmap.md，并核对相关实现、已有功能规格与 Git 状态；以实际完成状态判断下一项，不重复已完成的功能。
- 用户已指定功能时沿用该范围。路线图只有候选、含糊或与实际状态矛盾时，先用选项确认要规划的功能；“后续候选”不等于授权全部实施。基础文件缺失时说明缺口，不编造项目约定。
- 先简要解释目标、关键取舍和成功表现。课程原文、项目既定决策和本次建议要明确区分；不擅自换技术路线。

## 分组访谈，等待回答

按以下顺序逐组提问，可根据回答追问关键缺口。复用用户已明确的决定，不反复确认。

1. **Requirements**：目标用户、核心流程、范围与排除项、影响行为的数据和业务规则。
2. **Plan**：按依赖拆成带编号的小任务组，每组有可观察结果，并标明完成后暂停的位置。
3. **Validation**：成功与失败路径、数据副作用、适用的自动检查和浏览器检查，以及用户亲自体验的通过标准。

优先使用当前可用的选项提问工具；异步工具发出后等待实际回复，不能把默认选中或超时当成答案。没有提问工具时在对话中列出简短选项。每题说明取舍，允许自定义回答，不要求用户必须选推荐项。不依赖 Claude Code 专有的 AskUserQuestion 名称。

三组回答完整前，不写规格、改代码或创建分支。等待期间只能做独立的只读检查；不要跳到实现或声称问答已结束。

## 建立分支并写规格

- 问答完成后核对当前分支、工作区和已有规格目录。干净工作区可从当前确认的开发基线创建 feature/<feature-name>；已有对应功能分支则复用。分支重名但用途不明、基线不明或有不相关改动时先澄清，不 reset、强制覆盖或擅自 stash。
- 在 specs/YYYY-MM-DD-feature-name/ 建立 requirements.md、plan.md、validation.md，日期用 Asia/Shanghai 当日，功能名使用简短英文连字符。已有同一功能规格则更新，避免重复目录；同名目录属于其他任务时不要覆盖。
- requirements.md 记录目的、背景、已决定的范围、规则和排除项；plan.md 记录有依赖顺序的编号任务组和每组完成标准；validation.md 记录可实际执行的验收方法，初始均为待验证，不冒充执行结果。
- 三份文件引用基础规格，彼此范围一致。仅在新决策确实改变基础约定或路线图时同步最小相关修改，不复制整份基础文档。
- 写完核对三份内容、路径及 Git 差异，向用户说明决定、剩余未知项和第一组目标，随后暂停。此次调用不自动实现、执行迁移、更新 Changelog、提交、合并或推送。

## 课程来源与适配

[Build your own workflow 实际提示词](https://github.com/https-deeplearning-ai/sc-spec-driven-development-files/blob/main/Video13_Build_your_own_workflow/prompts.md)要求本地 feature-spec Skill、读取基础规格、建立分支及三组问答后写文件。本项目将建分支也延后到回答完成，使用 Codex 可用的提问方式，并保留逐组暂停的学习节奏。创建此 Skill 不等于已执行课程第二条“调用 Skill 规划下一功能”。
