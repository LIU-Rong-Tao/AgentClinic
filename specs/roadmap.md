本阶段具体需求、分组计划和执行证据见 2026-10-15-agents-ailments/。已完成共享布局、本地 PicoCSS、SQLite 初始化及三张业务表，已有 6 个 Agent、6 个病症和 8 对关联；普通启动只迁移，通过 pnpm seed 明确填充，一次 seed 的新增内容整体提交或回滚。/agents 列表与 /agents/:id 详情已完成三档浏览器验证，名称可进入真实详情；无关联明确显示“暂无已记录病症”。/ailments 两列表格、空状态与共享导航已完成三档浏览器验证。代码审查发现的测试缺口已修补，并验证故障注入时测试失败、恢复后通过；Changelog 已更新。此处保留阶段 2 的完成记录；后续 MVP 已完成本地收尾。

### 内部任务组

1. 复用与扩展布局：适配业务页面内容，加入实际已实现页面之间的导航，不放占位链接。
2. 数据基础：引入 SQLite、agents 与 ailments 表、普通 SQL 迁移及虚构种子数据，保存 agent 与病症的关联。
3. Agent 浏览：实现 /agents 列表与 /agents/:id 详情，展示名称、模型类型、状态与困扰。
4. 病症目录与关联：实现 /ailments，展示 agent 对应的一个或多个病症。
5. 验证：检查数据与页面一致、存在/不存在记录的行为、导航及三档响应式。具体数据模型和验收用例在下一节功能规格中确定。

完成标准：新数据库可通过迁移与种子数据复现；可以从列表进入正确详情，浏览病症及关联；关键行为测试和 375×812、768×1024、1440×900 浏览器检查通过。表格可在明确局部容器内滚动，页面本身无意外溢出。

不包含：疗法、预约、员工仪表盘、认证或业务数据编辑功能。列表与详情是浏览功能，不自动扩展成完整 CRUD。

## 阶段 3：疗法目录

2026-10-16 MVP 规格已建立于 `2026-10-16-mvp/`，将后续工作拆为五个可暂停的小组；第 1 组疗法与推荐关联数据已完成：新增 8 个疗法和 9 对推荐，旧数据保留且回滚验证通过。第 2 组疗法目录与 Agent 推荐展示也已完成：推荐显示名称、描述及匹配病症，去重、空状态、只读测试及三档浏览器检查通过。预约创建与冲突校验也已完成；仪表盘及状态确认更新也已实现并验证，统一错误页与基础日志已完成，自动串联复核已通过，用户体验验收已完成。

任务：建立 therapies 表与种子数据，提供 `/therapies`，建立病症到推荐疗法的映射。

完成标准：疗法列表与数据库一致，并能查到示例病症对应的推荐疗法。

## 阶段 4：预约（创建与校验已完成，2026-10-16）

任务：建立 appointments 表，保存 agent、治疗师、时间与状态；从 agent 详情页提供预约表单，增加基础校验与确认页面。

完成标准：有效提交创建正确预约并显示确认；不符合已定义校验规则的提交不会创建预约，并给出可理解的反馈。

## 阶段 5：员工仪表盘（已实现并验证，2026-10-16）

任务：提供 `/dashboard`，展示 Agent 总数、病症种类数和有效预约数（待开始与进行中）；默认展示有效预约，可切换全部记录并在开始前取消预约。按 MVP 问答暂不统计尚无明确业务定义的“待处理病症”，不扩展其他资料的通用增删改。

完成标准：汇总与数据库记录一致；当前阶段规格定义的记录管理操作可以完成，并在页面中反映结果。最终口径按已确认的 MVP 时间规则执行。

## 阶段 6：视觉与无障碍完善

任务：对各阶段已执行的响应式要求做跨页面复核，完善语义化 HTML、键盘导航与焦点样式；不将基本响应式延迟到此阶段。

完成标准：在阶段规格约定的桌面和窄屏尺寸下，核心内容可用；主要交互可通过键盘完成，焦点清晰可见。

## 阶段 7：健壮性处理（错误页与基础日志已完成，自动串联复核已通过，用户体验已接受）

任务：完善 404 和 500 页面、各表单输入处理与校验，以及基础请求日志中间件。

完成标准：不存在的地址和受控错误分别显示适当页面与状态码；已定义的无效输入被正确处理；请求产生预期日志。

## 阶段 8：访客反馈（实现、验收与审查完成）

目标：实际体验网站的人提交使用感受、问题与建议，员工可查看；不关联 Agent 或预约。保持课程演示定位，沿用现有技术栈，无新增依赖或外部服务。

详细规格见 `2026-10-16-feedback/`：昵称 50、反馈内容 2000、1～5 整数评分均必填，不收集邮箱；独立员工列表，最新在前。三组实施顺序为：①反馈表与数据校验；②访客表单、提交与结果提示；③员工列表、导航及整体验证。每组完成后暂停。

功能规格三组问答已完成；第 1 组反馈表与数据校验已实现，90 项测试、类型检查与构建通过。第 2 组访客表单、错误回填与提交结果已完成，94 项测试通过；第 3 组员工卡片列表已实现，97 项测试、类型检查和构建通过；用户已确认体验无问题；审查测试缺口已修补，Changelog 已更新。自动检查后由用户亲自提交并核对反馈，收到反馈后才标记通过。
