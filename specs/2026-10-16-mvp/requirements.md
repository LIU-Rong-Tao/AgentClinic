## 目标与技术边界

在已有只读页面之上形成“查看推荐疗法 → 创建预约 → 员工查看并在开始前取消”的最小闭环。覆盖路线图阶段 3～7 所需的疗法、预约、仪表盘、响应式及基本错误处理。

沿用 Node.js、TypeScript、Hono 服务端 JSX、SQLite/better-sqlite3、普通 SQL 迁移、本地 PicoCSS 与普通 CSS。保留现有页面、数据和已通过的测试。继续使用独立 pnpm seed，普通启动不填演示数据；已应用迁移不修改。

## 已确认的业务规则

### 疗法与推荐

- 提供 /therapies 疗法目录，展示虚构疗法名称与说明，建立病症到推荐疗法的关联。
- Agent 的候选疗法从其已记录病症汇总并去重；仅允许预约匹配的疗法，服务端重新验证关联，不能只依靠页面选项。
- 没有已记录病症或没有匹配疗法时说明原因，暂不允许预约。

### 预约创建与时间

- 从 Agent 详情进入预约流程，记录 Agent、疗法、治疗师、开始时间与状态，成功后提供清楚的确认信息。
- 治疗师来自固定的少量虚构名单，页面下拉选择，服务端拒绝名单外的值；不建设治疗师资料或管理页面。
- 按 Asia/Shanghai 展示并解释用户输入时间，避免受浏览器或服务器默认时区影响。
- 每次预约固定 30 分钟，仅整点或半点开始；服务端拒绝非法时间与非未来时间。
- 同一治疗师或同一 Agent 不能有重叠的 scheduled 预约；同时提交冲突请求也只能成功一个，冲突检查与写入必须保证一致性。相邻、不重叠的时段允许预约。
- cancelled 不再占用时段；本轮不设置营业时间、排班或治疗师与疗法的专属资格限制。
- 无效输入或冲突不得留下新预约，页面说明原因并允许纠正。

### 预约状态

- 未取消且开始前为待开始，开始时刻起为进行中，30 分钟结束时刻起为已结束。状态按服务器时间读取计算，刷新页面更新；无需定时写数据库。
- 只允许开始前取消；到开始时间即拒绝，包括开始前打开、开始后提交的旧确认页。取消不可恢复；移除人工完成入口，伪造 completed 请求返回 400。
- 旧 completed 历史记录保留并显示已结束，不重新激活。不修改 Agent 状态或病症。

### 员工仪表盘

- 显示 Agent 总数、病症种类数、有效预约数（待开始＋进行中）；默认只显示有效预约，可切换全部历史。
- 预约编号明确标注，不是数量。取消保留历史，再预约产生新编号。
- 取消前确认，服务器条件更新再次检查开始时间，过期或重复操作返回 409。

### 基础体验与健壮性

- 复用共享布局和品牌，导航只链接已实现页面；表单有清楚标签、错误提示和键盘焦点。
- 按 375×812、768×1024、1440×900 检查可读性及主要操作；页面无意外横向溢出，宽表格仅局部滚动。
- 完善基本 404/500 页面和请求日志；服务端异常不作为成功或空数据返回，不向页面暴露内部异常详情。日志记录请求方法、路径、状态与耗时，不记录完整表单内容。

## 不包含与实施前细化

不增加 Agent、病症、疗法的通用增删改、登录、邮件、支付、独立治疗师管理、排班或部署。保留本地课程演示定位，不将员工页面视为已有权限隔离。

疗法示例及关联、固定治疗师名单、具体字段与表单路由在对应小步先对照课程材料再细化；不提前编造课程数据。涉及业务含义变化时继续用选项确认。

本阶段按五组逐步实施并完成验收。提交、合并或推送作为后续独立步骤，不自动执行。

## 第 3 组实施约定（2026-10-16）

- 重复提交按时段冲突处理：第一笔成功，后续请求返回冲突提示，不增加记录；不引入提交令牌。
- 使用课程的 /agents/:id/appointments/new、POST /agents/:id/appointments、/agents/:id/appointments/:appointmentId 路由结构。确认页必须同时匹配 Agent 与预约编号。
- 固定虚构治疗师为 Dr. Ada、Dr. Turing、Dr. Hopper；这是本项目演示名单，不是课程数据。使用稳定 ID ada/turing/hopper。

## 第 4 组实施约定（最终修订，2026-10-16）

- 默认展示有效预约（待开始和进行中），按开始时间、ID 升序；统计不随筛选改变，历史记录可通过全部记录查看。
- 取消先显示确认页，GET 只读，POST 执行；服务端只接受 cancelled，并在取得写锁后检查 status='scheduled' 且 starts_at 大于当前时间。
- 重复取消、开始后提交的旧确认返回 409；人工完成或非法状态返回 400，不存在记录返回 404；成功后 303 返回原筛选。
- 满 30 分钟在读取时派生已结束，无需定时任务；旧 completed 数据仅兼容显示为已结束，不再生成。预约编号为记录身份，不代表有效数量。
- 不修改 Agent 或病症，不新增登录、排班或其他管理功能。

## 第 5 组第一小步：错误页与日志（2026-10-16）

- 采用简洁 404/500 页面，复用品牌布局，隐藏营业提示，提供首页和员工仪表盘入口；不提供自动重试或重新提交按钮。
- 404 表示页面或记录不存在；500 只说明请求未能正常处理。写操作异常时提醒先核对预约记录，避免把结果未知说成肯定未保存。
- 每个请求输出一条 JSON 控制台日志：method、path（不含查询字符串）、status、durationMs；不记录表单、请求头、异常堆栈或 SQL，不增加请求编号、日志文件或依赖。
- 受控故障仅由测试和临时验证程序注入，不增加应用故障路由或生产开关。
- 本小步不包含空库全流程复核、用户体验验收、Changelog 或 Git 收尾。
