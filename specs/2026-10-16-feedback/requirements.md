# 访客反馈：需求规格

2026-10-16：Requirements、Plan、Validation 三组问答已完成，第 1、2 组数据基础与访客提交已实现并验证；员工卡片列表已完成并验证，用户已确认体验无问题，审查收尾另行记录。

## 目标与依据

面向实际体验网站的课程学习者与演示访客，收集使用感受、问题与建议，由员工查看。保持虚构诊所及本地教学演示定位，不关联 Agent 或预约。

依据 mission.md、tech-stack.md、roadmap.md，以及课程相邻快照的[反馈示例规格](https://github.com/https-deeplearning-ai/sc-spec-driven-development-files/blob/main/Video13_Build_your_own_workflow/specs/2026-04-06-feedback-form/requirements.md)。课程示例包含可选邮箱和公开列表；本项目经问答明确不收集邮箱，采用独立员工列表。这些是本项目适配，不宣称为课程原文要求。

## 字段与输入规则

- 昵称必填，去除首尾空白后非空，上限 50。
- 反馈内容必填，去除首尾空白后非空，上限 2000；保留内部换行。
- 评分必填，只接受 1～5 的整数；不接受小数、缺失、非数字或超出范围的值。
- 长度单位采用浏览器 maxlength 与 JavaScript length 一致的 UTF-16 代码单元；普通汉字通常计 1，部分表情计 2。页面用“字符”描述，前后端一致校验，不把此细节作为产品说明重点。
- 服务端重新校验所有输入，不依赖浏览器限制；重复字段等不明确输入拒绝处理。
- 无效提交不写数据库，显示可理解的错误并保留已填写的文本和合法选择；所有回填及显示内容按文本转义。

## 页面与保存行为

- 访客提交页只显示表单和提交结果，不展示其他人的反馈。具体路由在实施前按项目惯例确定。
- 成功保存一条记录后使用 POST/redirect/GET，跳转结果页；刷新结果页不再次写入。显式再次提交是新反馈，本轮不做防连点令牌或内容去重。
- SQLite 保存昵称、内容、整数评分、记录编号及服务端提交时间；提交时间按 Asia/Shanghai 展示。新增普通 SQL 迁移，不修改已应用迁移。
- 从员工仪表盘提供独立反馈列表入口，按提交时间倒序、同时间按 ID 倒序；显示昵称、评分、内容及提交时间，空库显示明确空状态。
- 本轮展示全部反馈，不增加搜索、分页、编辑、删除、回复、邮箱、邮件通知或外部服务。后续规模需求单独规划。
- 无登录或权限隔离；“员工查看”是页面用途，不是访问控制承诺，不能声称反馈仅员工可访问。

## 技术与范围

沿用 Hono 服务端 JSX、SQLite/better-sqlite3、普通 SQL 迁移、本地 PicoCSS、Vitest，无新增依赖或客户端框架。现有错误处理与请求日志继续适用，日志不记录反馈内容；保留已有业务与数据。

实现按 plan.md 三组逐步授权，每组完成后暂停；用户体验反馈后才标记功能验收通过，不自动更新 Changelog、提交、合并或推送。

## 第 1 组实现约定

新增 007_feedback.sql：id、nickname、message、rating、created_at（服务端 UTC ISO 时间）。长度和 Unicode 空白规范化由共享保存入口按 JavaScript UTF-16 口径校验；SQLite 另设非空文本、整数 1～5 评分约束，不使用不同长度口径替代服务端校验。保存入口接收未知类型，拒绝数组等重复字段表示，失败返回字段错误和原文本，不写入。单条 INSERT 原子保存，数据库异常继续抛给上层处理。普通启动只迁移，无反馈 seed；本组不新增页面或 HTTP 路由。

## 第 2 组实现约定

主导航增加“反馈”，GET /feedback 展示表单，POST /feedback 校验并保存；失败返回 400 并回填输入，成功以 303 跳转 GET /feedback/success。结果页仅显示通用收到提示和返回入口，不查询或展示他人反馈。沿用现有 500 处理和日志，不记录输入内容；不新增员工列表。

## 第 3 组实现约定

从仪表盘进入 /dashboard/feedback，采用逐条卡片，上方显示昵称、评分及北京时间，下方显示完整反馈并保留换行；长文本自动折行。按 created_at DESC、id DESC 排序，无记录显示明确空状态。本轮无权限隔离。
